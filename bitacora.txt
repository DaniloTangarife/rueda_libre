MINIRETO 1 — Kilómetro 0: repositorio y página base
------------------------------------------
¿Qué hice?
- Creé la carpeta local rueda_libre, inicialicé Git y la conecté a un repositorio público de GitHub.
- Creé la estructura inicial: index.html, paginas/, img/ (con logo), css/ y bitacora.txt.
- Escribí la estructura base de index.html: <!DOCTYPE html>, <html lang="es">, <meta charset="UTF-8">, <meta name="viewport">, <meta name="description">, <title> y el <body> con un <h1> y un <p> de bienvenida.
- Abrí la página con Live Server y analicé la petición en DevTools (Network).
- Probé una ruta inexistente y analicé la respuesta del servidor.

Datos de la petición principal (DevTools → Network):
- URL completa:  http://127.0.0.1:5500/index.html
- Protocolo:     HTTP/1.1
- Host:          127.0.0.1
- Puerto:        5500
- Ruta:          /index.html
- Método:        GET
- Estado:        200 OK

Ruta inexistente:
- Probé: /promociones.html
- Estado: 404 Not Found
- Significado: el servidor no encontró el recurso solicitado.

Roles de HTML, CSS y JavaScript:
- HTML: estructura y contenido (ej. el <h1> de la portada y la tabla de tarifas).
- CSS: presentación (ej. css/styles.css con la paleta y tipografías).
- JavaScript: interactividad (ej. el bundle de Bootstrap para el menú hamburguesa).

¿Qué aprendí?
A configurar un repositorio con Git y GitHub, crear un documento HTML válido y leer en DevTools cómo el navegador pide y recibe la página.

Controles elegidos por dato:

| Dato                  | Control                                | name           |
|-----------------------|----------------------------------------|----------------|
| Nombre completo       | <input type="text">                    | nombre         |
| Documento             | <input type="text">                    | documento      |

Reglas traducidas a atributos:

| Campo              | Regla del cliente                      | Atributos aplicados                                                     |
|--------------------|----------------------------------------|-------------------------------------------------------------------------|

- Ambos patrones llevan title para que el navegador muestre el mensaje de formato esperado.

MINIRETO 10 — Navegación con estados y sin conflictos
------------------------------------------
¿Qué hice?
- Agregué las reglas del compañero: #menu a { color: var(--gris-asfalto); } y .activo { color: var(--verde-ruta); font-weight: 600; }.
- Asigné id="menu" a la lista del menú y la clase activo al enlace de la página actual en cada página.

Análisis del conflicto de especificidad:
- #menu a → especificidad (1,0,1): 1 id + 0 clases + 1 elemento.
- .activo → especificidad (0,1,0): 0 ids + 1 clase + 0 elementos.
- Resultado: #menu a gana porque tiene mayor especificidad (1,0,1 > 0,1,0). La clase .activo por sí sola nunca se aplicaba.
- Solución sin !important: escribí el selector combinado #menu a.activo, cuya especificidad es (1,1,1) y vence a #menu a (1,0,1). Se aplicó el color verde y el peso 600 al enlace activo.

- Estilicé los enlaces del menú con el selector descendiente #menu a y definí :hover y :focus con outline visible.
- Creé la clase .btn-cta para los enlaces de llamada a la acción con apariencia de botón y estados hover/focus.
- Definí un indicador de foco visible para los campos del formulario con box-shadow y border-color en input:focus.
- Recorrí las tres páginas con Tab y comprobé que el foco siempre se ve.

Verificación de contraste:
El color Verde Ruta (#1E7A4F) sobre Crema (#FAF6EF) tiene 4.8:1, cumple con 4.5:1 para texto normal.

¿Qué aprendí?
A resolver conflictos de cascada y especificidad calculando los pesos, sin recurrir a !important, y a definir estados :hover y :focus visibles.

------------------------------------------
MINIRETO 1 — Encabezado, menú y pie con Flexbox
------------------------------------------
¿Qué hice?
- En el encabezado puse el nombre del negocio en un extremo y el menú en el otro, centrados verticalmente con flex-direction: row, justify-content: space-between y align-items: center (a partir de 768px; en móvil es flex-direction: column con align-items: center).
- Convertí la lista del menú en un contenedor flexible con gap; eliminé márgenes e inline-block.
- Agregué flex-wrap: wrap al menú para que los enlaces bajen de línea cuando no quepan.
- Organicé el pie en tres bloques en fila (marca, contacto y horario), alineados arriba con align-items: flex-start y separados con justify-content: space-between.

Comportamiento al estrechar la ventana (observado en DevTools):
- Escritorio (≥768px): marca a la izquierda y menú a la derecha en una fila; pie con tres bloques en fila.
- Móvil (<768px): marca arriba y menú debajo centrado; pie en columna apilada.

¿Qué aprendí?
A usar Flexbox para distribuir y alinear elementos en una dimensión.

MINIRETO 2 — Flota en cuadrícula con Grid y Flexbox

¿Qué hice?

- Construí la cuadrícula con Grid usando repeat(auto-fit, minmax(min(100%, 250px), 1fr)), sin media queries, con gap uniforme.
- Dentro de cada tarjeta usé Flexbox en columna y margin-top: auto para que el botón "Reservar" quede siempre al final.
- Agregué el séptimo modelo (Tándem) y comprobé que la cuadrícula se reorganiza sin tocar el CSS.

¿Qué aprendí?
Que Grid con auto-fit y minmax construye una cuadrícula adaptable sin media queries, y que Flexbox en columna con margin-top: auto alinea los CTA al fondo.

Nota: tras la migración a Bootstrap (Semana 2, reto 7), esta sección usa row g-4 + col-*; las reglas .grid-flota y .tarjeta-bicicleta quedaron comentadas en styles.css como referencia didáctica.

------------------------------------------
MINIRETO 3 — Layout en dos dimensiones (Grid + Flex)

Decisiones de Flexbox vs Grid por caso:

| Caso               | Técnica  | Por qué |
|--------------------|----------|---------|
| Portada            | Grid 1fr 1fr (desde 1200px) | Dos bloques principales; control claro de proporciones. |

| Reservas 8/4       | Grid 2fr 1fr (desde 1200px) | Proporción 2:1 explícita con unidades fr. |
| Fila del formulario| Flex (row, flex:1, gap) | Solo una dirección horizontal. |
| Encabezado         | Flex (row, space-between, align-items:center) | Una dimensión: marca vs. menú. |
| Pie de página      | Flex (row, space-between, align-items:flex-start, wrap) | Tres bloques en una línea con quiebre en móvil. |

En escritorio el layout coincide con el boceto. Las columnas se definen con fr. El menú, la flota y la validación del formulario siguen funcionando.

MINIRETO 6 (Semana 3) — Landing responsive (Mobile-First)
------------------------------------------
¿Qué revisé a 360 px (celular) y qué se rompía?
1. El encabezado tenía los enlaces, el logo y el botón en una sola fila, lo que causaba desbordamiento y amontonamiento.
2. La grilla de rutas se veía muy apretada al intentar mostrar las 3 columnas fijas en el celular.

4. La franja de inscripción y el pie de página tenían contenido desalineado y pegado.

¿Qué hice?
- Reescribí las clases de layout con enfoque mobile-first:
  · Las clases sin prefijo corresponden al celular (1 columna).
  · Usé sm: (640px) para tablet pequeña (2 columnas).
  · Usé lg: (1024px) para escritorio (3 y 4 columnas).
- Rutas: cambié a grid-cols-1 sm:grid-cols-2 lg:grid-cols-3.
- Pasos: cambié a grid-cols-1 sm:grid-cols-2 lg:grid-cols-4.
- Encabezado: apilado por defecto (flex-col), y en fila desde md (md:flex-row). Oculté los enlaces de navegación en el celular con hidden md:flex, dejando solo visible el botón "Inscríbete".
- Ajusté tamaños de letra y espaciados: el h1 del hero ahora crece a lg:text-8xl; el padding de las secciones aumentó con py-16 md:py-24.

| 768px  | En fila (enlaces visibles)   | 2                | 2                | En fila           | No                |
| 1024px | En fila                      | 3                | 4                | En fila           | No                |

3. Generación del CSS minificado y medición
Para medir el tamaño real del CSS de Tailwind, ejecuté el CLI con la opción --minify:
    npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --minify
Luego abrí la landing en el navegador y, en DevTools → Network, filtré por "CSS" y "JS":
- CSS de Tailwind (output.css minificado): ~33.7 KB (tamaño transferido por la red; el archivo en disco pesa 33.7 KB).

En la versión principal (v2.0 con Bootstrap), al revisar Network para la misma landing, el peso era:
- Bootstrap CSS (v5.3.3 CDN minificado): ~232 KB.
- Bootstrap JS Bundle (v5.3.3 CDN minificado): ~80 KB.
- Total aproximado en la v2.0: ~312 KB solo en el framework.

4. Comparativa de frameworks (Bootstrap vs Tailwind)

| Criterio | Bootstrap (v2.0) | Tailwind (v3 Nocturna) |
|----------|------------------|--------------------------|
| Curva de aprendizaje | Baja al inicio (clases como btn, card listas para usar), pero alta si quieres personalizar profundo (peleas con especificidad y !important). | Media-alta al inicio (debes conocer las utilidades), pero una vez entiendes el sistema, el control es total y no hay CSS "basura". |
| Personalización | Limitada. Para salir del diseño estándar tienes que sobrescribir variables (--bs-*) o escribir CSS propio, lo que a veces genera conflictos de cascada. | Total. El @theme permite definir exactamente los colores, fuentes y espaciados de la marca, y las utilidades se generan a partir de ahí. |
| Tamaño final | Pesado. El CSS y JS de Bootstrap suman ~312 KB (cargando todo el framework). | Ligero. Tailwind genera CSS on-demand: solo lo que usas. El archivo minificado para esta landing pesa ~33.7 KB y no requiere JS. |
| Casos de uso | Ideal para prototipos rápidos, paneles de administración o proyectos donde la identidad visual no es prioridad y se necesita velocidad. | Ideal para sitios con identidad de marca fuerte, landings de campaña, o cuando el rendimiento y el peso del CSS son críticos. |

5. Recomendación para Rueda Libre
Recomiendo Tailwind CSS para la próxima versión de todo el sitio de Rueda Libre.
Razones basadas en los datos:
- El peso: Tailwind reduce el peso del framework en más de un 85 % (33.7 KB vs 312 KB), lo que mejora los tiempos de carga, especialmente en celulares (que es el 70 % del tráfico de la campaña).
- La identidad: Rueda Libre tiene una paleta de marca muy definida (Verde Ruta, Naranja Pedal, etc.) y Tailwind con @theme permite aplicarla de forma consistente sin conflictos.
- La curva: aunque requiere aprender las utilidades, el equipo ya tiene experiencia con ambas herramientas, y la curva se compensa con creces con el control y la limpieza del HTML resultante.
